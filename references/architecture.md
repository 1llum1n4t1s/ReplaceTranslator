## 翻訳エンジン translator.js（速度と網羅の要）
- **ビューポート優先**: IntersectionObserver で各ブロックを observe し、可視(+`PREFETCH_MARGIN` 1200px 先読み)に入った順にテキストノードを enqueue。`sortTopDown` で**ページ上→下の優先順位**に並べてから投げる
- **直列 flush + 動的バッチ + ワーカープール**: `flush()` は `flushing` ガードで**1本に直列化**（同時多発を防ぎ 429 を抑える＝BatchTuner が育つ）。共有カーソルから**その時点の `currentBatchSize`** 個ずつ取り出すので、自動学習の成長が同一 flush 内で即反映される。並列度は `concurrencyFor()`（LLM=`CONCURRENCY` 24 / MyMemory 等 `batch:false` は直列 1 / **provider が `maxConcurrency` を宣言していればそれで上限**＝無料枠 RPM の低い Gemini は 3 で 429/503 多発を回避）。初回 flush は即時、以降 200ms デバウンス
- **プロバイダ別の並列上限 `maxConcurrency`**: 無料枠の RPM が低い社（Gemini flash ~10 RPM）は既定 24 並列だと起動直後に 429/503 が多発 → リトライ枯渇で大量 skip → 未翻訳になる。`actions.js` の provider 定義に `maxConcurrency` を足すと `concurrencyFor()` が `min(maxConcurrency, CONCURRENCY)` に絞る（有料枠は遅くなる代償。レート制限の緩い社は無指定＝24 のまま）
- **失敗の局所化**: 1 バッチが 429/通信エラーでも全停止せず、指数バックオフでリトライ→ダメなら飛ばして続行。`incomplete` は同じ大きさで即時再送せず、background が返した縮小値と失敗 batch の半分の小さい方で未訳分を再キューする。入力サイズ起因の HTTP 400/413 も同じ縮小経路へ流し、1 要素まで縮んだ入力は同一内容を再送しない。NMT(MyMemory)の 429 は解けないので即諦める。**MyMemory の `translateEach` は 429/403(共有キー/IP の rate-limit)を 1 件検知したら `giveUp` で残りノードを原文ドレイン**＝quota 枯渇後に残り全件へ無駄 GET を撃たない（`too_long` の局所スキップとは区別し giveUp しない）
- **fetch には必ずタイムアウトを課す**: SW の全 LLM/画像 fetch は `withTimeout(signal)`＝`AbortSignal.any([signal, AbortSignal.timeout(FETCH_TIMEOUT_MS 60s)])` を通す。これが無いと half-open 接続や無応答ストリームで `fetch`/`reader.read()` が永久ハングし、ワーカーが stuck → `flush` の `flushing` ガードが張り付き → ページ翻訳が無言で永久停止する。timeout 中断は `TimeoutError`(name)で reject するため各 catch の `AbortError`(=ユーザー中断→`aborted`)判定に当たらず `network` 系（translator の transient リトライ対象）へ落ちる（**error 種別を増やさず D-003 のメッセージ契約 drift を避ける最小設計**）。新規 fetch を足すときも `signal: withTimeout(signal)` を使う
- **恒久エラーは握り潰さず理由を出す**: LLM の HTTP **400/401/403/404** は設定/リクエスト形状が原因で全バッチ同型に必ず失敗するため `fatal` 扱いで全体中断し `notifyProgress("error", {detail})` で通知する（401/403=キー無効・400=リクエスト不正・404=モデル無し）。429/通信などの一時エラーだけ skip して継続。popup は `errorText(detail)` で「`<provider>`: HTTP 400 — `<API本文の error.message>`」等に展開し、ただの「エラー」表示で原因不明にならないようにする（無言 skip で「未翻訳なのにエラーも出ない」を防ぐ）
- **未訳 skip は「完了」と嘘をつかず partial で出す**: 429/503/通信エラーはリトライ（5xx もバックオフ対象）後それでも解けなければ skip して継続するが、その未訳ノード数を `droppedTransient` に数え、done 時に `notifyProgress("done", {partial:true})` を立てる。MyMemory は `translateEach` が失敗要素の `failedIndices` を返し、原文と同じ正当な翻訳結果と区別して入力上限・部分的なquota失敗だけを同様に数える。SW `handleFrameProgress` が全フレームの partial を OR 集約して最終 done に乗せ、popup は入力制限/レート制限/混雑を含む `statusPartial` を出す。一部は訳せているので state は `done` のまま（FAB は翻訳済み表示）。「完了なのに訳されていない」を防ぐ
- **Shadow DOM**: `collectNodes` は TreeWalker でなく**開いた shadowRoot を辿る DFS**。辿った shadow root は MutationObserver にも登録し内部の動的更新も拾う（closed shadow は仕様上不可）
- **iframe**: `allFrames:true` 注入で各フレームが独立翻訳。広告枠対策に `frameHasEnoughText()`（サブフレームは翻訳対象 50 字未満なら訳さない＝Immersive の mainFrameMinTextCount 相当。メインフレームは常時）
- **SPA 追従**: `onMutate` で `location.href` 変化を検知 + `popstate` リスナー → `scheduleReingest()` で遷移後ページを訳し直す
- **遅延描画パネルの取りこぼし対策（`zeroSizedBlocks` + `ResizeObserver`・本命）**: qiankun 等 micro-frontend の open Shadow DOM パネルや非同期チャートは、初回 ingest 時に**幅も高さも 0（`zeroSized`）でパネルが潰れた状態**で `io.observe` され `observedBlocks` に入る。チャート描画（2〜4s+）で後から高さが付くが、(1) IO は **0×0→サイズ付与の in-viewport 遷移を発火しないことがある**（スクロールで初めて発火）、(2) `ingest` の `observedBlocks.has(block)→continue` が rect を読み直さず**永久スキップ**する。これで「FAB が翻訳済み(`__rt-on`)表示なのにパネルが全部英語」になる（`REINGEST_DELAYS` を伸ばしても全 tick が continue で弾かれ無効＝この機序を裏付け）。手動 FAB が効くのは `startTranslate` が WeakSet を作り直し描画後の rect を near として読み直すため＝純粋なタイミング race。**対策**：`blockMeta` が `zeroSized`(幅も高さも 0)を返し、`zeroSizedBlocks` WeakSet で**初回 0×0 で observe した block だけ**を限定追跡（0-height だが幅のある block は visible=true で near 判定に乗るため対象外）。`ingest` はこの block に限り毎回 near 再評価し、高さ確定＆near なら `io.unobserve`＋即翻訳へ promote（普通の画面外 block は従来どおり rect 非読み取りで IO 任せ＝reflow 増を回避）。さらに **`ResizeObserver`（`ro`/`onResize`）** で 0×0 block の高さ確定を**決定論的に**能動検知（canvas/svg のピクセル描画は DOM mutation を伴わずレイアウトだけ変える＝MO/IO では拾えないため RO だけが捕捉）。`promoteSizedBlock` を ingest/onResize 共用の単一ソースにし、`flushedBlocks`/`isConnected`/`zeroSized`/`near` をガードして二重取り込みを防止。RO 未対応環境は `ro=null` で `zeroSizedBlocks` の reingest 再評価がフォールバック。`stopObservers`/`startTranslate` で `ro` 破棄・`zeroSizedBlocks` 再生成（復元/context 失効でリーク無し）
- **遅延コンテンツの再走査（`REINGEST_DELAYS`）**: 初回翻訳 / SPA 遷移後、`REINGEST_DELAYS=[350,1200,2500,4500,7500,12000]` の各時点で `ingest(body)` を再走査（上記 zeroSized 再評価が毎 ingest で走るので、RO 不在時の保険＋新規 shadow root の observer 登録補完を兼ねる）。`scheduleReingest` は貼り直し前に `reingestTimers` を解除（SPA 連続遷移の多重起動を畳む）、`stopObservers` でも解除。done は `announced` で 2 重通知を防ぐので遅延取り込みが後から訳しても FAB は翻訳済みのまま中身だけ埋まる
- **動的追加**: MutationObserver（`childList`+`subtree`+`characterData`+`attributes`＝`MO_OPTS` に集約・本体/shadow root 共通）。`characterData` mutation は訳済みノード(`translatedNodes.has`)に対して**3分岐**: (a)自分の書いた訳文(`writtenValue`)のまま=無視(自己再発火防止)、(b)ページが**原文へ書き戻し**(SPA 仮想 DOM の同値再適用)=`writtenValue` の訳文を**同期再適用して継続**(delete/ingest/API ゼロ・ちらつき無し)、(c)別テキストへの差し替え(SPA/チャットの文言更新)=訳済みマーク/原文記録を捨てて訳し直す。分岐順序と `writtenValue` の undefined ガードを厳守する((b)の自己書き換えは(a)で弾かれループしない)
- **同一原文の再翻訳を避ける（context-aware exact dedupe + L1/L2/L3 cache）**: `flush` は同一 flush 内の **完全一致原文 + 完全一致文脈**だけを 1 要素へ集約し、返った訳文を該当 Text node へ fan-out する（trim/Unicode 正規化なし＝原文・文脈の 1 文字差や空白差は別入力）。文脈は同一 block 内または前後 block の原文 preview を最大240文字へ制限して採り、孤立要素は query/hash を除いた pathname とページタイトルを補助にする。LLM には miss ごとに `{text, context}` を送り、system prompt で context は曖昧性解消専用・翻訳対象外・信頼しないページ内容と明示する。文脈入力非対応の MyMemory 等 `batch:false` NMT は context を空にして従来の exact-text 経路を維持する。content の `translationMemo` は同じ frame/run の SPA 再レンダを API なしで復元する L1。background は HTTP(S) の通常ページだけを対象に、`origin + pathname + provider + model + source/target + promptVersion + 原文 + 文脈` をキーとする bounded L2 を `storage.session` に保持し、同じページ範囲の再読込・別 tab/frame でも再利用する。さらに popup の「永続翻訳キャッシュ」をユーザーが明示的に ON にした場合だけ同じレコードを L3 (`storage.local`) に保存し、ブラウザ再起動後も再利用する。既定は OFF で、UI に原文と訳文を端末へ保存することを明記し、OFF へ戻した時点で L2/L3 とメモリ上の読み込み済みレコードを削除する。L2/L3 は最大30日・2000件・合計200万文字・1件5万文字を上限とし、incognito/file/quick は保存しない。in-flight 中の文字変更は現在値を再照合し、古い訳を適用せず変更後の値を再キューする
- **属性トグルで表示される要素を取りこぼさない**: `attributes` 監視（`ATTR_FILTER`=class/style/hidden/open/aria-hidden/aria-expanded/`data-state`＝Radix/shadcn）で `display:none`→表示のドロップダウン/モーダル/タブ/アコーディオンを拾う。IO は display 切替を取りこぼすことがある（`display:contents`/ポータル等）ため属性駆動で補う。属性は高頻度変化なので `scheduleAttrReingest` が **250ms デバウンス集約**して再 ingest（`collectNodes` が既訳/監視中ブロックを skip するので冪等）、class 多発ページは **対象 >30 で body 1回再走査へ畳む**。我々（translator）は属性を書き換えないので自己再発火なし（fab/画像オーバーレイは `SKIP_CLOSEST` で除外済み）
- **原文復元**: 翻訳ノードは WeakMap(`originalMap`) に原文保持、復元で nodeValue を戻す。`runId` インクリメントで進行中ループを中断
- **拡張 context 失効ハードニング**: リロード/更新で置き去りになった旧 content script が `chrome.runtime.sendMessage` で例外を投げる問題に対し、静かに停止する。`translator`/`image-translator` は `contextAlive()`/`shutdown()` + try/catch、`fab` は送信ラッパ（`send()` の try/catch + `p.catch`）で同等にハードニングする（手段は違うが効果は同じ）。再注入時は `ExtUtil.claimScript()` が manifest version と現在の `chrome.runtime` object identity を marker に保持し、同一 context 内の重複だけを抑止する。旧 boolean marker・別 version・別 runtime は stale として再初期化するため、更新/リロード後のオンデマンド注入が旧 guard に阻まれない
- **runtime message の権限境界**: SW は `sender.id===chrome.runtime.id` を必須にし、`MessagePolicy` で action ごとに送信元を分離する。`APPLY_SETTINGS` / `GET_STATE` / `GET_MODELS` は popup 等の拡張ページ限定、`TRANSLATION_PROGRESS` / `TRANSLATE_IMAGE` は content 限定、`TRANSLATE_BATCH` は content と popup の `quick:true` だけを許可する。FAB の `TRANSLATE_PAGE` / `RESTORE_PAGE` は content から許可するが、対象は `msg.tabId` を無視して `sender.tab.id` へ固定し、別タブ操作への権限拡大を防ぐ
- **再注入の冪等性**: translator/fab/image/selection と actions/lang は各 `__rt*Loaded` marker を `ExtUtil.claimScript()` で取得する。同一 runtime/version では listener/observer を二重登録せず、更新/リロード後は再初期化する

## 動的モデル取得 & バッチ自動学習
- **モデル一覧**: `GET_MODELS` で各社 models API から動的取得（`buildModelsRequest`/`parseModels`）。`fetchModels` が新しい順(created / Gemini はバージョン)に並べ、`ProviderApi.filterTranslationModels` で翻訳に使えない非テキスト系（embed/whisper/tts/transcribe/audio/realtime/dall-e/image/**imagine**/video/veo/sora/moderation/guard/search）と**ローリングエイリアス（`latest` を含む ID。中身が予告なく差し替わるため無日付の公開版 ID に寄せる。Anthropic だけは日付入りしか配信しないため除外せず `anthropicAlias` がエイリアス化+重複排除）**を除外する。ただし `Providers.models` に明示した curated ID は日付入りしか公開されない正規モデルとして残す（OpenRouter の `deepseek/deepseek-v4-flash-0731` 等）。その後 `pickPriced` で **`ModelPricing.lookup` が価格を返すモデルだけ**に絞ってから **上位 10 件** を `MODELS_CACHE` に保存（`fetchedAt` も併記＝将来の TTL/診断用。現状 TTL 判定は無く取得は force 時のみ＝下記参照）（価格不明＝"—" でコスト比較できないモデルはユーザーに見せない。ただし全件価格不明なら空一覧回避の保険で全件返す）。各モデルは models.dev 由来の公式表示名 `name`（"GPT-5.6 Sol" 等・"(latest)" 装飾は除去済み）を持ち、popup は `name || id` で表示・tooltip に実 ID を併記。選択中が一覧に無ければ `migrateModel` が先頭へ（判定は表示用 top10 でなく全取得 `allIds`＝価格圏外の有効モデルを勝手に載せ替えない）。fallback（同梱モデルの静的表示）にも同じ価格フィルタを適用
- **取得は force のときだけ通信** = 「API キー入力後（保存）」と「モデル更新ボタン押下時」。provider 切替/popup 起動は通信せずキャッシュ/同梱フォールバック表示
- **廃止モデルの動的フォールバック（テキスト翻訳のみ）**: SW の `TRANSLATE_BATCH` ハンドラが翻訳バッチの **404 を `isModelGone` で検知 → `resolveFallbackModel`（provider.defaultModel、既定自体が廃止なら live `/models` 先頭）→ `persistModelSwitch` で settings に保存 → 同バッチを 1 回だけ再試行**。`modelFallback`/`resolvingFallback` Map で 10 並列の同時 404 でも解決を 1 回に集約。画像翻訳は `/models` が入力 modality を保証しないため、この汎用フォールバックを使わない。`provider.visionModel` の明示モデルだけを使い、404 はそのまま返す（text-only モデルへ画像を再送しない fail-closed）。vision の現行値は provider 定義で保守する
- **廃止モデルの静的保険 `RETIRED_MODELS`(actions.js)**: 通信ゼロ・キー前でも効く保険。各社が retire した ID を Set に列挙すると `normalizeSettings` が保存設定の該当モデルを既定へ自動移行する。**既定モデル自体が RETIRED のときは null（未選択 → live 取得で解決）に倒し、廃止 ID を書き戻して実行時 404 自己修復と往復しないようにする**。同梱 `models`/`defaultModel`/`DEFAULT_SETTINGS.models` が廃止 ID を指さないことは `test/actions.test.js` の不変条件テスト（`defaultModel`/`visionModel` ∉ `RETIRED_MODELS` を振る舞いで検査）で守る＝廃止期日が来て RETIRED に足したら既定も現行へ更新する、を CI が強制（足し忘れるとテストが赤くなる）。`model-pricing.js` は部分一致表なので過去 ID の価格行は残してよい（廃止 ID は一覧に出ず lookup されない。`lookup` は**世代境界ガード**＝一致キー直後が数字/ドットなら別世代として弾き、`grok-4.5`→`grok-4` のような誤った高価格のサイレント適用を防ぎ価格不明に倒す）。確認済み廃止: Gemini 2.0系(2026-06-01)、xAI grok-4-1-fast系(2026-05-15)、Groq kimi-k2、**DeepSeek deepseek-chat/deepseek-reasoner(2026-07-24。公式 API は v4 系のみ＝既定を `deepseek-v4-flash` へ移行。OpenRouter 側も同名 ID が消滅したため `deepseek/deepseek-*` も RETIRED に列挙し、同梱一覧は `deepseek/deepseek-v4-flash-0731`＝無日付の公開版が無いので Anthropic と同じ日付入り扱い)**。廃止予定（動的フォールバックが死亡時に吸収）: Gemini/OpenRouter gemini-2.5-flash(2026-10-16)
- **恒久エラーの可視化**: LLM の 400/401/403/404 は fatal(全体中断+error通知)。429 は本文を見て `quotaScope`(translator.js) が日次(RPD)/残高切れ(`PerDay`/`insufficient_quota`)を判定し、解けない 429 は fatal 化して popup が `statusQuotaDaily`「利用上限に達した」を表示（リトライ無駄を回避）。分次(RPM)/5xx/通信の一時 429 は従来どおりリトライ→残れば partial
- **Anthropic は日付入りスナップショット ID しか配信しない** → `anthropicAlias()` で日付を剥がしてエイリアス化し重複排除（除外正規表現で全弾きしないこと）
- **推論設定はモデル別に保存し、未指定は許容最小値**: `reasoningEfforts[provider][model]` に popup の明示値だけを保存し、未指定の「自動」は従来どおり翻訳向け最小値を使う。`reasoningProfile` が UI の選択肢と request builder の検証を共有し、未対応値・未知系列は推測しない。`tuneReasoning` が OpenAI/xAI/Groq の `reasoning_effort`、OpenRouter の統一 `reasoning`、DeepSeek v4 の thinking toggle + effort、Fugu の `reasoning.effort` をモデル系列別に設定する。Anthropic は `output_config.effort`、Gemini 2.5 は明示 budget（自動はflash/lite 0・pro 128）、Gemini 3+ は `thinkingLevel` を使う。通常・stream・画像の3経路へ同じ保存値を渡し、翻訳キャッシュキーにも effort を含める
- **価格**: 各社 models API は価格を返さないため、SW の `ensurePricing` が **models.dev の api.json から動的取得**（force 取得時のみ通信・TTL 1h・`PRICING_CACHE` に保存し SW 再起動でもキャッシュで即動く）して `ModelPricing.setDynamic` に流し込む。lookup は **動的の完全一致（ベンダ接頭辞 ID は末尾照合）> 同梱表の部分一致・最長優先** の順で、取得失敗/未収録時だけ `model-pricing.js` の同梱表にフォールバック。新モデルが出ても拡張リリース無しで価格が付き `pickPriced` の一覧に載る（同梱表の手更新は必須でなくなったが、オフライン初回のフォールバック品質のため大型新世代は追記推奨）
- **バッチサイズは自動学習**: `BatchTuner`(actions.js・純粋関数)が texts/秒 を hill-climbing（DEFAULT 50 / STEP 25 / MIN5 / MAX100、429 でサイズ半減）。`background` はメモリ(`tuningMem`)で同期更新し、storage 永続化はデバウンス集約（**毎バッチ storage I/O と 10 並列の read-modify-write 競合を避ける**）
- **トークン集計はメモリ保持・非表示**: `recordUsage` が `usageMem`(`tokenUsage[YYYY-MM][provider]`) に加算しデバウンス永続化。popup のトークン表示 UI は撤去済み（表示は無いが集計は残る）

## 画像翻訳 — ホバー/右クリックの手動のみ（設定トグルは廃止・vision 対応プロバイダ選択時のみホバーボタン表示）
- **手動翻訳に一本化**（一括翻訳 `translateAllImages` / 後追い watcher / iframe 一括注入は廃止＝「読みたい1枚だけ訳す」）。`image-translator.js` が画像ホバーで「訳」ボタンを出し、クリックで `translateImg`→`TRANSLATE_IMAGE`、background が画像を fetch→base64→LLM vision に投げ、`parseImageBlocks` の正規化 bbox をオーバーレイ。`<img>` 限定（**動画は送らない**。background でも非画像 mime を弾く）。**同一画像の in-flight 中は再送しない**（`inflightImgs` WeakSet。`imageRequestIds` は「古い応答を描かない」世代ガードで送信は止めないため、これが無いと「…」中の連打が vision 二重課金になる。応答/lastError/catch で必ず解除）
- **画像URLのSSRF境界**: `ImageRequestPolicy` が HTTPS 以外、userinfo、localhost/単一ラベル/内部TLD、private・loopback・link-local IP を拒否する。DNS上同値の終端ドット付きFQDNは判定前に終端ドットを除去し、`printer.local.` / `nas.corp.` の回避を防ぐ。private IPv4 をドット/ハイフン区切りで埋め込んだホスト名と、`localtest.me` / `nip.io` / `sslip.io` 等の既知 wildcard DNS suffix も拒否する。IPv6 はURL正規化後の8ワードへ展開し、IPv4-compatible / mapped、NAT64 WKP、6to4 に埋め込まれたprivate IPv4、deprecated site-local、RFC 8215のlocal-use prefixも拒否する。取得は `redirect:"manual"`・`credentials:"omit"` とし、最終URLも同じポリシーで再検証する。Chrome stable/Firefox 共通で最終DNS解決先を検査する拡張APIは無いため、任意の公開FQDNがprivate IPへ解決されるケースまでは保証せず、画像翻訳をユーザーの明示クリックに限定する境界も維持する
- **画像バイトを decoder/API の前で検証**: `ImageRequestPolicy.inspectBytes` が Content-Type だけを信用せずマジックバイトから実体 MIME を確定し、本拡張が画像入力として扱う PNG/JPEG/GIF/WebP だけを許可する。4形式はヘッダ寸法が正の値で読めることを必須にし、`MAX_IMAGE_PIXELS`(25MP) 超過を base64 化・vision 送信・`createImageBitmap` より前に拒否する。SVG/BMP/AVIF/HEIC と壊れた画像は、展開後サイズを検証できないため `not_image` で拒否する
- **右クリック「この画像を翻訳」（`rt-translate-image`・contexts:["image"]）**: SW `contextMenus.onClicked` → `triggerImageTranslate(tabId, info.srcUrl, info.frameId)` → 共通ヘルパ `sendCsOrInject` が **`info.frameId` のフレームへ** `TRANSLATE_IMAGE_CS` を送る（受信端不在なら `executeScript`+`insertCSS` でそのフレームだけオンデマンド注入→再送＝selection と同じ既存タブ救済。**iframe 内画像もこの frameId 配送＋注入で翻訳できる**。常駐はトップのみ＝広告枠コスト回避を維持）。frameId を常に明示送信するのは、全フレーム配信だと注入済み iframe が同一 srcUrl の別画像を重複処理し得るため。content は `contextmenu`（capture/passive）で `imgAtPoint` 解決した `ctxImg` を第一候補にし（オーバーレイ被りも拾える）、注入直後（contextmenu 未観測）は `findBySrcUrl`（**open Shadow DOM を含む全imgをDFS・ビューポート内優先・同率は面積大**＝同一 URL 複製画像の誤解決防止）で解決 → 既存 `translateImg`。明示操作なので `showImageButton` 設定には従わず、進捗/結果（…/原/×+title 理由）は共有ホバーボタン UI で可視化。既知アニメ画像は SW へ再送せず ×+`imgErrAnimated` のみ（画像 fetch の無駄打ち防止）
- **アニメーション画像は翻訳対象外（ボタンを出さない）**: アニメ GIF / アニメ WebP / APNG は `createImageBitmap` が先頭フレームしかデコードせず、canvas inpaint で焼くと元 `<img>` のアニメが静止画に隠れて固まる。SW `fetchImageBytes` が取得バイトの構造マーカー（WebP=`ANIM`／APNG=`acTL`／GIF=`NETSCAPE2.0` か GCE `0x21 0xF9 0x04` が2個以上）で `isAnimatedImage` 判定し、アニメなら vision を呼ぶ前に `{ok:false, error:"animated"}` を返す（API 消費ゼロ・静止 GIF/WebP/PNG は素通り＝誤検出ほぼ無し）。content は受け取った画像を `animatedImgs` WeakSet に登録し、以後 `onMouseOver` で「訳」ボタンを出さない。**cross-origin 画像のバイトは content から読めずホバー時点では判定不能**なので、初回クリックで確定→登録する方式（初回だけ理由 `imgErrAnimated` を tooltip に短く出して隠す）。静止 WebP/PNG/JPEG は従来どおり翻訳できる
- **設定トグル `imageTranslate` は廃止**: 翻訳はホバー/右クリック+クリックの明示操作でしか起きない（＝勝手に翻訳しない）ので、自動翻訳の gate は撤去・`SettingsSchema` からも除去済み
- **「訳」ボタンは画像翻訳(vision)対応プロバイダ選択中だけ出す**: 判定は `Providers.supportsImage(id)`＝`visionModel` の有無（対応: openai/anthropic/gemini/openrouter/groq、非対応: xai/deepseek/fugu/mymemory）。`contentFlagsOf` がこれを `CONTENT_FLAGS.imageCapable` に載せ、image-translator が `onMouseOver` で読んで**非対応プロバイダ選択中は「訳」ボタンを出さない**（クリックしても `no_vision` になるだけのため無意味な操作を見せない）。`storage.onChanged` で provider 切替に即追従（開いているページもリロード不要）。**既に翻訳済みの画像は「原(戻す)」を残す**（翻訳後に非対応へ切替えても取り残さない。`showImageButton` OFF でも同じ例外＝右クリック翻訳した画像を個別に戻せる。この「原」候補判定は `.__rt-img-wrap` 内かの安価チェックを `imgAtPoint` より先に行い、OFF/非対応時の mouseover 走査コストをゼロにしている）。既定 provider は mymemory(非対応)なので**既定ではボタンが出ない**。SW の `translateImage` も `supportsImage` で `no_vision` を判定する（旧 `provider.batch===false` は mymemory のみ拾い、xai/deepseek は text モデルで vision を試して HTTP エラーになっていた）。`ensureContentFlags` は `imageCapable` 欠落の旧フォーマットを更新時に補完する
- **オーバーレイ被り・open Shadow DOM内画像でもボタンを出す（`imgAtPoint`）**: 多くのサイト（カード型リンク・ホバー効果）は画像の上に `<a>` やオーバーレイを重ねるため `mouseover` の `e.target` が img にならない。open Shadow DOM由来イベントはdocument側でtargetがhostへリターゲットされるため、まず`composedPath()`から内側のimgを解決し、残るオーバーレイ被りは`elementsFromPointDeep`がカーソル直下の要素スタックだけを`ShadowRoot.elementsFromPoint`へ再帰して被さった要素の下のeligibleなimgを拾う（全DOM走査はしない）。`onMouseOut`はrelatedTargetでなく**矩形ベース**（カーソルが対象画像/ボタンの矩形から外れたときだけ隠す）でカード内子要素跨ぎのちらつきを防ぐ。URLフォールバック・ページ復元・context失効時の後始末は`openRoots`のDFSで同じopen root集合を扱い、shadow内だけオーバーレイや監視タイマーが残らないようにする
- **`<picture>` 対応（`ensureWrap` が picture ごと包む）**: `<picture>` 直下 img を span で直接包むと img が `<picture>` の外に出て `<source>` 解像度選択が外れ別解像度/プレースホルダに化ける。`ensureWrap` は親が `<picture>` のとき **`<picture>` 自体を host として包み**（picture に display:block/width/height:100% を付与、退避 style は復元時に戻す）source 選択を保つ。`isTranslated`/`revertImg` は `img.closest(".__rt-img-wrap")`、`unwrapImage` は host（picture か img）を外へ戻す。退避 style 復元は `restorePrevStyle` に集約。実機検証（実 `<picture>`）で picture ごとラップ時に currentSrc が source 選択を維持・unwrap で完全復元を確認済み
- **1 枚ずつ元に戻せる**: 翻訳成功でボタンは「原」に切替（`setBtnMode`／`isTranslated` で判定）、クリックで `revertImg`→`unwrapImage` がその画像だけオーバーレイ除去＋ラッパー解除して原文に戻す（`btn.__rt-img-btn-on` は墨色）
- ページ翻訳とは**非連動**。`APPLY_TRANSLATE_CS` では何もせず、`APPLY_RESTORE_CS`（原文復元）でだけ `clearAllImages`（=全 wrap を `unwrapImage`）がオーバーレイを消す
- **垂直位置は `cy`（テキストの縦中央/midline）に帯の中心を合わせる**: VLM は枠上端 `box.y` より縦中央を桁違いに安定して当てるため、`buildImagePrompt` は `cy` を**最重要フィールド**として要求し、`parseImageBlocks` が取り込む（欠落時は `box.y+box.h/2`）。`renderBlocks` は `top = cy*imgH − boxHpx/2`（`align-items:center` で訳文中央=cy）で配置し、`box.y` の系統的な上ズレに依存しない（**訳文が原文より上にずれる問題の対策**）。水平は `box.x/box.w` のまま
- **Gemini はネイティブ bbox 形式**を使う: `buildImagePromptGemini` が `box_2d=[ymin,xmin,ymax,xmax]`(0–1000 正規化・object detection の訓練フォーマット)＋`responseSchema` で取得し、`parseImageBlocks` の gemini 分岐が `{x,y,w,h}0..1`+`cy` へ変換（**x/y 反転が致命的なので test 必須**）。他社は共通プロンプト（`cy`+`{x,y,w,h}`）。bbox 精度はモデル依存で、画像翻訳は Gemini が最も正確
- 速度/コスト優先: 各 provider の軽量 `visionModel` を既定使用、出力上限 `IMAGE_MAX_OUTPUT_TOKENS`(2048)。`ensureWrap` は元 img の表示ボックス(`getBoundingClientRect`)・display・object-fit を wrap に px 固定で引き継ぎ（レスポンシブ画像が inline-block ラップで拡大されるのを防ぐ）、復元時に元 inline style を戻す。オーバーレイ文字サイズは `fitFontSize` が訳文 span を**枠(幅×高さ)に収まる最大フォント(9〜40px)へ二分探索でフィット**（係数ベースを廃止し多行枠での巨大化を解消）。上限は文字面積モデル（`L=√(boxW·boxH/(len·0.6))`）で推定した1行ぶんの高さで**常にクランプ**し、単一行の箱は箱高さで頭打ち。`original` が来ないとき（vision が省略）は訳文長×2 を原文長の概算に使う（**原文欠落時に上限が箱高さ＝最大化して訳文が巨大化するのを防ぐ**・短い訳語が縦長枠で膨らむのも防ぐ）。枠の高さは box に固定し（`min-height` だと訳文が伸びて隣に重なる）、極小枠は ~14px を下限に、9px でも収まらない多行は `align-items:flex-start` で先頭行を残す。vision 対応 LLM のみ（MyMemory 不可）
- **単独行は均一余白へ横展開して原文サイズ 1 行を保つ（英→全角で訳文が英文 box を超え縮小される対策）**: 日本語は全角で英語 OCR/vision box.w の ~1.3 倍幅が要り、box.w に閉じ込めると `targetFont` でも幅あふれ→折返し縮小で原文より小さくなる。中央寄せメール等は左右に均一余白があるので、単独行を `availHWForFlat`（同 y 帯の左右最近隣 block か画像端までの安全余白）で `effInnerW=innerW+2*min(l,r)`(上限 `W*0.96`) へ横展開し、font 計測・折返し・面積上限をこの幅で行う（`blk.__rtEffInnerW` で drawInpaintBlock へ伝達）。展開条件は **`isSingle && pb.flat`** ＝ flat 背景は背景色 fill で消すため flat 時のみ展開する。**flat 経路の消去 fillRect は広げない**（訳文の overhang は均一余白＝原文の墨が無い領域に乗るので消去不要）。多段組（水平に隣 block）は `availHWForFlat` が隣 block 手前で頭打ちにする。中央(`x+w/2`)対称展開なので描画位置は不変
- **オーバーレイのライトボックス追従/掃除（クリックで表示が崩れる対策）**: canvas は px 固定 wrap に張り付くため、reddit 等が画像を**外部リサイズ/別位置へ移動/別 img へ複製/差替**してライトボックスを開くと、元位置に取り残されて崩れる。`startFollow` が翻訳後に `setInterval`(1s) で「wrap 切離し/img 消失・移動/src 差替/矩形 <1px/描画時サイズから ±8px 超の外部リサイズ」を検出し、取り残し canvas を `unwrapImage` で掃除する（再描画でなく掃除に徹する＝ライトボックスの大きい画像はユーザーが訳し直せば横展開＋解像度合わせで可読になる）。`stopFollow` を `unwrapImage` 冒頭と `shutdown` で呼びタイマー leak と context 失効後の残留を防ぐ。`wrap.__rtChk` で二重起動防止
- **診断ログ `dbg()`（既定無音）**: 焼き込みフォント問題の切り分け用。ページ console で `localStorage.setItem("__rt_debug","1")` を立てたときだけ `console.debug("[rt-img]", …)` を出す（経路 inpaint/html・canvas 解像度 W×H・scale・各 block の box.h/single/flat/target/areaCap/avail/eff/font/wrap 行数）。未設定で完全無音・本番コンテキスト消費ゼロ。**翻訳内容の切り分けには `img-result`** ＝ 各 block の `orig`(vision が読んだ原文) / `trans`(訳文) を出す。`orig` が既に崩れていれば vision の読み取り段、`orig` 正常で `trans` 崩れなら翻訳段、と一目で確定できる
- **「×」ボタンは失敗理由を title で出す（無言失敗の可視化）**: `translateImg` の結果が空のとき「×」を出すが、`res.ok` だが空＝翻訳対象テキスト無し/全ロゴ（正常・短く 1.5s で戻す）と、`res.ok===false`＝失敗を区別する。失敗時は `imgErrorText(res)` が SW の error 種別（`no_vision`/`no_api_key`/`forbidden_target`/`image_too_large`/`not_image`/`http`+status/`aborted`）を i18n 文言に展開して `btn.title` に載せ、ホバーで原因が読めるよう「×」を 4s 保持する。**vision 非対応プロバイダ（`Providers.supportsImage()===false`＝visionModel 無し: mymemory/xai/deepseek/fugu）は必ず `no_vision`** になる（ただし非対応選択中はそもそもホバーの「訳」ボタンを出さないので、この「×」は主に vision 対応 provider でのキー無し/quota/SSRF/HTTP 失敗の可視化に効く）。これが無いと失敗が全部無言の「×」に潰れて原因不明になる（ページ翻訳の `errorText` 相当をホバー tooltip で提供）。文言キーは `_locales/{en,ja}` の `imgNoText`/`imgErr*`
- `image-translator.js` は manifest `content_scripts` で**トップフレームのみ常駐**（iframe には注入しない）
- **canvas inpaint（既定の描画方式・原文消去+焼き込み・依存ゼロ）**: 透けた HTML オーバーレイ（原文の上に訳文が乗りズレが目立つ）に代えて、原文を消して訳文を画像に焼き込む。`renderTranslated`→`renderInpaint` が SW 取得済み base64 を `createImageBitmap(blob)` で**CORS-safe に再構築**（cross-origin `<img>` 直 draw は canvas を taint し getImageData/toDataURL を封じるため、`translateImage` は `{image:{base64,mime}}` を content にも返す）→ 元画像を canvas に描き各ブロックを `drawInpaintBlock` で処理し、`__rt-img-layer` クラスの canvas を wrap 最前面に被せる（既存 isTranslated/unwrapImage/revertImg がそのまま機能）。`ringStats` が box 外周リングをサンプリングし**平坦背景**(std<24)なら背景色 fill で原文消去+明暗で文字色決定、**textured** なら半透明帯で隠す。**透過背景は単色箱にしない**＝`ringStats` は alpha も集計し、flat 経路は背景が概ね透明(`alpha<0.5`)なら不透明 fill を省く（透過 PNG/SVG の透明部が単色箱になるのを防ぐ。`flatBoxOf` も透過を flat 対象から外し行間ストリップ fill を乗せない）。この alpha ゲートの誤発火源（object-fit:cover/contain 再現で生じる描画域外のレターボックス透明画素を ring が拾い不透明画像でも fill を省いて原文ゴーストが残る回帰）は、`ringStats` が `renderInpaint` の設定する `inpaintFit`(=`fitDrawRect` の描画域)でサンプリング域をクランプして断つ（描画域外の透明画素は色/alpha 集計から除外。恒等＝object-fit:fill/アスペクト一致時は全面で従来完全維持）。訳文は `fitCanvasFont`（measureText 二分探索+CJK 折り返し）で枠にフィットし `cy` 中央へ。巨大画像は `INPAINT_MAX_SIDE`(4096)でスケール。画像バイト無し/失敗時は `renderBlocks`（HTML オーバーレイ）へフォールバック
- **object-fit:cover/contain を canvas 上で再現する（cover クロップ画像で原文が消えない回帰の根治）**: `renderInpaint` は canvas を表示ボックス px で作り `drawImage` で**ビットマップ全体を引き伸ばす**ため、X(Twitter) のように `object-fit:cover` でクロップ表示される画像はそのままだと画像が歪む。これを避けるため一時期 `fitMismatch` ゲート（cover/contain でアスペクト差>8% なら canvas を諦め HTML オーバーレイへ）を入れたが、**X は cover が常態なので毎回ゲートに掛かり原文除去が丸ごと無効化**された（暗い半透明箱だけ乗り原文が透ける回帰）。根治として `fitDrawRect` が cover/contain の表示クロップ/レターボックスを **`drawImage` の 9 引数で複製**し、`remapBlocksToFit` が VLM の block 座標（フル画像基準 0..1）を**同じ変換で canvas 正規化座標へ写し**、`blockInView` が cover で見切れた block を除外する。これで cover/contain でも歪まず原文消去＋訳文配置が両立する（`object-fit:fill`／アスペクト一致は `fr` が全面＝**恒等変換で従来完全維持**）。ゲート(`fitMismatch`)は撤去済み。`renderTranslated` は base64 があれば常に canvas を試し、失敗時のみ `renderBlocks` へ
- **焼き込み解像度を表示ボックスに合わせる（訳文が薄く細く見える主因の根治）**: `renderInpaint` は canvas 論理解像度を**ナチュラル画像サイズでなく「表示ボックス px × dpr」**(`want=min(dpr, max(bmp/disp))`・等倍〜拡大のみ・`INPAINT_MAX_SIDE`4096 上限)で生成する。旧来のナチュラル解像度で焼いて CSS で縮小表示すると、1〜2px の細い CJK 縦画が bilinear で灰色に溶けて薄く見えた。表示サイズに解像度を合わせて**縮小経路を消す**と glyph がシャープに出る。`img.getBoundingClientRect()` が未レイアウト(width<1)のときだけ従来のナチュラル解像度へフォールバック。`scale=W/dispW`(≒dpr)を draw 関数へ渡し物理可読下限の換算に使う。CSS `.__rt-img-canvas{image-rendering:auto}` は拡大表示残ケースの smooth 保険
- **焼き込みフォントは原文より一回り大きく焼く（CJK 可読性優先・訳文が小さい問題の根治・det は戻さない）**: det 締め(dilation 0.08/0.12)や vision の visible-glyph box で `box.h` は font の ~0.7 倍(cap-height 相当)に痩せるので、`box.h` 枠フィットだと原文サイズすら下回る。さらに**同じ px でも CJK は英字より窮屈**なので、原文サイズ復元(box.h*1.34)では「変わってない」と見える。`computeGroupFonts` は **単独行 `font=box.h*H_TO_FONT(1.85)`**（原文の見た目=box.h*~1.43 より一回り上）、**複数行段落 `font=pitch*PITCH_TO_FONT(0.78)`**（`cy` 間隔=行送りの median・外れ値除去）で決める。連結は色一致を「両方 flat のときだけ」要求する `shouldLinkRowsPitch`（textured 段落も pitch 計測対象）。`ABS_MAX`40 で絶対上限。**面積モデル G5(areaCap) は診断ログ用に残すが font の縮小には使わない**（旧: areaCap で textured 行を target 割れまで潰していた＝小さく焼かれる主因。`2 行に折れば大きく入る訳文`まで潰すのを止め、実あふれは下記 avail/幅フィットに委ねる）。**行重なりは構造的に防ぐ**: `availPitchFor` が**真上・真下 両方向**の同カラム(x 重なり)最近隣との cy 間隔の小さい側を返し（訳文は cy 中央寄せで上下対称に伸びるため・**下方向だけだと段落最終行が無限大になり上の行へ食い込む**）、font を `avail*availClamp`(`0.96`<1.0)で頭打ち＋幅/高さがあふれる block だけ `fitCanvasFont(予算=avail*availClamp)` で詰める。各行の高さ ≤ 0.9×間隔 となり上下とも >=10% の隙間が残る。縦書き(aspect>2.2 & 細幅)/1 文字/極小(h<10px)/textured は `fonts[idx]=0`＝従来 fit に委譲。`drawInpaintBlock` は **`forcedFont>0` を無条件採用**（computeGroupFonts が avail+幅で重なり安全に確定した上限なので、**minReadable 底上げは fallback(forcedFont=0)のときだけ**＝高 DPI で底上げが avail を超え隣行へ食い込むのを防ぐ）、**同色細縁**(stroke を fill と同色で `min(1.5,font*0.06)`px・縮小/低面積のコントラスト低下を補強。textured の halo は stroke パスにだけ載せ二重縁を回避)を fill 前に重ねる
- **行間ストリップ埋め（段落の行間に残る原文黒帯の対策・依存ゼロ）**: vision は段落を「行ごとの別 block」で返しがちで、各行を独立 fill すると隣接行の隙間に原文の上下端ストロークが帯状に残る。`renderInpaint` は per-block ループの**前**に `fillInterlineStrips` を 1 回呼び、`flatBoxOf`(drawInpaintBlock と同一の cy ベース box)で flat 同色行のみ採取→cy 昇順→隣接ペアが `shouldLinkRows`（**同色 `colorDist<40`／x 重なり>0.5／高さ比 0.5〜2.0／gap 0〜0.7 行高** の全 AND）を満たすときだけ、**x 重なり区間 × 行間の隙間だけ**を背景色で fill する（dy を増やすと隣行訳文背景を侵食するため隙間連結で対処）。段組・別段落・別色パネル・ロゴ↔本文は AND ガードで非連結＝ロゴを消さない
- **ロゴ/ブランド語の翻訳重畳を除外（kind 主役・辞書は隔離保険）**: vision プロンプトが各 block に `kind:"text"|"logo"` を付け（`parseImageBlocks` が両分岐で取り込み・欠落/未知は `text` に倒し本文 recall を守る・Gemini は `responseSchema` にも `kind` を追加）、content の `filterBlocks` が `kind==="logo"` を捨てる。kind 非対応モデル向けの保険 `looksLikeBrandWordmark` は **端帯(cy<0.12||>0.88)+短語(≤2)+英数形+固定 `BRAND_WORDS`** の AND でのみ弾く（kind が来ていれば走らせない＝本文の "Claude" を誤爆させない）。全 block が logo で空なら "×" 表示（無言 NG を防ぐ）。完全除外は不可前提
- **box の文字インクスナップ（カバレッジ向上・依存ゼロ）**: 平坦背景のとき `snapToInk` が box(+余白)内で背景色と差>~48 の画素=文字インクの外接矩形を求め、**「ink 外接 ∪ 元 box」＝縮めず広げるのみ**で消去域を補正する（**行頭グリフを削らない**＝VLM の右ズレ box が行頭1〜2字を取りこぼす問題の対策）。探索域は**左を字高基準で厚く非対称**（左 `max(0.30w,0.7h)`／右 `0.14w`）に取り、左右の拡張は `maxExtend=min(W*0.04,h*1.5)` で頭打ち＝**離れたグラフィック（ロゴ等）へ到達させない**。`drawInpaintBlock` の flat fill マージンも**字高(h)基準の非対称**（左 `0.34h`厚め／右 `0.16h`／上下 `0.30h`）で、横6%固定では覆えなかった行頭ゴースト・行間/周囲の薄残りを消す。訳文配置は snap 後 box 中央のまま（配置回帰なし）。文字無し/探索域ほぼ全面インクなら null で元 box 維持。textured/暗背景/極小box は非変更。**検出漏れ行（block が無い行）は消去側では救えない**ため、vision プロンプト（`buildImagePrompt`/`buildImagePromptGemini`）に「全行を漏れなく検出」「box 左端は行頭 glyph の左端まで」を明記して発生源側で軽減

## UI 構成（popup 3タブ + FAB）
- **popup 3タブ**: 「翻訳」＝**言語(元・先) → 翻訳・復元ボタン + status → クイック翻訳 → 設定群(`.opts`)** の順。設定群は「全ページ自動翻訳 / 永続翻訳キャッシュ / フローティングボタン(＋不透明度) / 選択テキスト翻訳(表示方法) / 画像翻訳ボタン」を**同じ `.switch-field`（ラベル + 説明 + チェックボックス）に揃えて 1 枠へ統合**する（自動翻訳だけ独立カード + スライドスイッチだった旧形は廃止。操作子が 2 種類混ざるのを避ける）。永続翻訳キャッシュは原文・訳文を端末へ保存するため既定 OFF の明示 opt-in とし、説明文で最大保存期間と OFF 時の削除を開示する。「API設定」＝**各プロバイダのカードに「選択ラジオ + 名前 + バッジ + キー入力 + 取得リンク」を合体**＋選択中サービスのモデル一覧(更新ボタン・コスト相対バー)＋選択モデル専用の effort select。effort は対応モデルだけ表示し、「自動（推奨）」とそのモデルが受理する値だけを並べる。ただし自動時の実値と同じ明示候補は重複表示せず、見出しのモデル名は一覧と同じ公式表示名を使う。「除外リスト」＝自動翻訳ブラックリストを1行1件のtextareaで編集し、450ms debounceまたはblurで自動保存する
- **API設定はアコーディオン**: プロバイダが 8 社に増えて縦が伸びるため、キー入力欄（`.pc-body`）は**選択中カードだけ開く**（CSS `.provider-card:not(.selected) .pc-body { display:none }` ＋ 開くとき `fadeDown`）。未選択カードはヘッダ（ラジオ + 名前 + バッジ）だけのコンパクト表示。カードヘッダのクリックで `selectProvider` → `renderProviderList` が `.selected` を付け替え＝そのカードのキー欄が開く。キーは従来どおり blur 自動保存（カード切替時は旧入力の blur が先に走り保存される）
- **キーは blur 自動保存**: 入力欄からフォーカスが外れたら保存し、そのカードに緑チェックを一瞬出す（保存ボタンは無い）
- FAB は content 常駐（`fab.js`+`fab.css`、トップフレームのみ）。クリックで `TRANSLATE_PAGE`/`RESTORE_PAGE`、`TRANSLATION_PROGRESS` で状態同期。**レール型タブの形状**＝画面右端に密着し、**ホバー/フォーカスでページ側へ「にょき！」とせり出す**（`width:30px→44px`・せり出しは fab.css の `:hover:not(.__rt-dragging)` が担当）。中央は**文字を描かないアイコン**（地球儀=翻訳前 / 戻り矢印=翻訳済み。インライン SVG・`stroke=currentColor` で状態別 `--ink` を継承、出し分けは `.__rt-on` で CSS）。**表面デザインはフラットデザイン**（ブランド色 = **生成り × 墨 × 朱** を維持し質感を排する）。生成りのベタ地（グラデ/繊維テクスチャ/厚みの影/エンボスなし）+ 1px のフラットな輪郭線 + **ページに面した左端の朱のフラットバー(`::after`・ベタ)**（状態の署名色）、非ホバー時は**半透明(`--rest:.72`)**。状態は色で表す（**翻訳前=生成り `#f4f1e9` + 墨アイコン / 翻訳済み=朱でベタ塗り `#d8462b`＋バー・アイコンを生成りに反転**）、**処理中(`__rt-loading`)は朱バーをフラットにパルス(`rt-fab-pulse`)。pointer-events は殺さずクリックで中止可**（autoTranslate 固着での無反応化を防ぐ）。**翻訳失敗(`error`)時は地球儀アイコンを朱(`--rail-deep`)へ寄せた `__rt-error` 表示にし、失敗理由（キー無効/quota/HTTP 等）を `title`/`aria-label` に出す**＝popup を開かなくてもホバーで原因が読める（自動翻訳/FAB の無言失敗を防ぐ。理由文言は popup の `errorText` と同じ i18n キーを `errSummary` が共有）。SW は直近エラーをタブ単位で `lastErrorByTab` に保持し `GET_STATE` で返すので、**エラー後に popup を開いても理由を再表示**できる（TTL 90s）。`RESTORE_PAGE` は translator 未注入タブでも SW が `restored` を能動中継するので FAB が確実に未翻訳へ戻る。**ダークモード対応**（`prefers-color-scheme: dark` で暗いスレート紙 + ダーク朱）。**右端固定で縦方向のみドラッグ移動**（水平は CSS の `right:0` に固定し右側から離れない。`applyTop`/`clampTop` で縦のみ動かし、縦位置は**比率**で `StorageKeys.FAB_POSITION` に `{ratio}` 保存してリサイズに追従＝`applyRatio`/`ratioFromTop`。旧 `{top}`/`{left,top}` 形式は ratio へ換算）。`#__rt_fab` の id プレフィックス + `all:initial` でページ CSS と衝突しない（Shadow DOM は使わず content_scripts の css で直接注入）
- **自動翻訳**（`autoTranslate`）: **popup の「全ページ自動翻訳」トグルのみ**が永続フラグを保存する。ワンショット翻訳（popup 翻訳ボタン / FAB / 右クリック）は永続化しない（1 ページ訳しただけで以後の全ページが自動翻訳されるのを防ぐ）。ON なら常駐 fab.js が開いたページを自動翻訳するが、SWの`translatePage(tabId, manual=false)`は世代採番・abortより先に`AutoTranslateBlacklist.matches(tab.url, settings.autoTranslateBlacklist)`を確認し、一致時は注入/API呼び出しなしで`blacklisted:true`を返す。`manual:true`のpopup/FAB/右クリックはブラックリストをバイパスする。進捗は `TRANSLATION_PROGRESS` で 3 者同期（トグルの ON/OFF はワンショット進捗では切り替えない）。**OFF にしたら今見ているタブを原文へ戻す**（`on ? TRANSLATE_PAGE : RESTORE_PAGE` を `getActiveTab().id` のみへ送る＝裏タブは触らない）
- **自動翻訳ブラックリスト**（`autoTranslateBlacklist`）: `SettingsSchema.normalize`が文字列/配列を行単位でtrim・空行除去・重複排除して配列保存する。ホスト規則（`x.com`）はhostname完全一致、`*`を含むホスト規則（`192.168.*`）はglob一致、scheme付きURL（`https://photos.google.com/`）は同一originの指定パス以下に一致する。右クリックの`rt-auto-translate-site`は全contextに表示し、現在URLが一致中なら「対象外から削除」、未一致なら「対象外に追加」へ更新する。追加は現在hostnameを1行追加し、削除は現在URLに一致する全行を除去して実際に自動翻訳対象へ戻す。http/https以外は無効化する
- **translate ⇄ restore の順序競合をタブ世代トークンで断つ（OFF を確実に勝たせる・本命）**: `translatePage`/`restorePage` は別々の async メッセージハンドラでタブ単位の直列化が無い。autoTranslate ON でページを開くと fab が `TRANSLATE_PAGE` を送り、`translatePage` が `injectTranslator`(executeScript・低速) を **await している最中**にユーザーが OFF にすると、`restorePage` が先に `APPLY_RESTORE_CS` で戻しても、後から await が解けた `translatePage` が `APPLY_TRANSLATE_CS` を**後着送信**し `startTranslate` が新しい `runId` を採番して再翻訳する（`restore()` の `runId++` は旧ループしか止められず後発 translate を打ち消せない）＝「OFF にしたのに今のタブが翻訳済みのまま」になる。対策: SW に `tabGen`(Map: tabId→世代番号) を持ち、`translatePage`/`restorePage` 冒頭で `bumpTabGen` で採番、`translatePage` は `APPLY_TRANSLATE_CS` を**送る直前に自分の世代が最新か確認**し、await 中に restore（や別の翻訳）が世代を進めていたら送信を取り止める（`{ok:true, superseded:true}` で静かに無視＝popup の Error 表示を出さない）。どの到達順でも**最後の意図が OFF なら確実に原文へ戻り**、`tabId` キーなので裏タブ非干渉。`tabs.onRemoved` で `tabGen.delete`。content 改変は不要（発生源の SW で stale な再翻訳を断つ）
- **クイック翻訳**（popup「翻訳」タブ末尾・常時表示）: 上部の翻訳元⇄翻訳先を流用し、入力を debounce して `TRANSLATE_BATCH` に 1 件投げる。ページは翻訳しない短文用。コピー/クリア/文字数/`Ctrl+Enter`。**翻訳元/翻訳先セレクトの変更でも訳し直す**（`rerunQuickTranslate` フック。`run()` を呼ぶ経路が入力イベントしか無いと、入力済みのまま言語を切り替えたときに旧言語の訳文が残る）。言語切替は明示操作なので debounce せず即実行し、`run()` 冒頭の `await pendingSave` が設定保存の確定を待つので新しい言語で翻訳される（古い応答は `reqId` 世代ガードで破棄）
- **popup のデザインは「生成り × 墨 × 朱」を保ったまま質感を引き算で上げる**（`popup.css` 冒頭のコメントが規範）。守る規則: ①**朱のグラデーションは主ボタン 1 箇所だけ**（他はベタ＋ヘアライン。tab-ink もベタ。例外はコスト相対バー＝安い藍→高い朱の階調に意味があるため）、②境界は低コントラストの `--hair`（1px 実線 `--rule` は面の区切り用に限る）、③**面は上端 1px ハイライト `--sheen`（inset）＋ 3 層影 `--shadow-sm/md`、入力欄は逆に inset の凹み**で役割を対比させる、④角丸と余白は `--r-sm/md/lg`(8/12/16px) のスケールに乗せる、⑤トランジションは `--ease` に統一。**ダークは朱の明度が高く白文字がコントラスト不足**（約 2.6:1）なので `.btn.primary` の文字を墨へ反転する（この上書きは後勝ちにするため `.btn.primary` 定義より後ろに置く）

## 選択テキスト翻訳（ホットキー / 右クリックで浮遊バブル表示）
- **明示操作でのみ起動**: `selection-translator.js`（content・**トップフレームのみ**常駐、fab/image と同じ manifest content_scripts に同梱）が、`chrome.commands` のホットキー（`translate-selection`・既定 `Ctrl+Shift+L`／Mac `Command+Shift+L`、`chrome://extensions/shortcuts`(Firefox=about:addons) で再割り当て可）または右クリック「選択テキストを翻訳」(`rt-translate-selection`・`contexts:["selection"]`) を受けて、選択範囲の近くに**浮遊バブル**で訳文を出す。「選択しただけ」では送らない（FAB の `isTrusted`・画像のクリック要求と同じ "勝手に送らない" 原則）
- **起動経路**: SW はページ選択を直接読めないため、ホットキー(`commands.onCommand`)/右クリック(`contextMenus.onClicked`)とも `triggerSelectionTranslate(tabId)` が content に `TRANSLATE_SELECTION_CS` を送るだけ。content が `window.getSelection()` を読み、`selection.getRangeAt(0).getBoundingClientRect()` を anchor にバブルを置き、**popup クイック翻訳と同形**で `TRANSLATE_BATCH`(`texts:[選択文]`+`quick:true`) を投げる（API キーは content に渡さず SW 保管値を使う）
- **既存タブへのオンデマンド注入フォールバック（本命）**: selection-translator は常駐 content だが、Chrome は**拡張の更新/リロード前から開いていたタブには content_scripts を遡及注入しない**。そのまま `tabs.sendMessage` すると受信端不在で `.catch` に黙殺され、バブルもエラーも出ず**無反応**になる（ホットキー/右クリック両経路とも沈黙）。`triggerSelectionTranslate` は共通ヘルパ **`sendCsOrInject`**（selection/image 右クリックで共用・frameId 対応）で、**送信失敗時に `scripting.executeScript`(actions.js/selection-translator.js)+`insertCSS`(selection-translator.css) でオンデマンド注入してから再送**する。runtime/version-aware な冪等ガード(`__rtActionsLoaded`/`__rtSelectionLoaded`)により、生存中の同一 context への誤再注入は無害で、更新/リロード後の stale marker は再初期化される。常駐リスナ生存時は初回 sendMessage が成功し executeScript は走らない（オーバーヘッド 0）
- **ページ翻訳とは独立**: 選択翻訳は「いま見えている選択テキスト」をそのまま訳す（翻訳済みページの訳文選択は実質 no-op だが、ページ翻訳が skip した箇所＝code/pre/notranslate/短文は原文のままなので訳せる）。**`quick:true` は `trackController` をスキップ**し、`abortTab`（FAB 復元/再翻訳）に巻き込まれて中断されないようにする（popup クイック翻訳は元々 `sender.tab` 無しで未追跡＝無影響）。content は `reqId` ガードで stale 応答を捨てる
- **ON/OFF フラグは持たない（常時有効）**: 明示操作（ホットキー/右クリック）でしか起きないので無効化の必要が無く、popup は**表示方法 `selectionMode`（バブル/インライン）だけ**を出す。旧 `selectionTranslate` は撤去済み（`SettingsSchema.normalize` が未知キーとして捨てるので旧インストールの `false` も残らない＝UI に出ない設定で無反応になるのを防ぐ）。`contentFlagsOf` は `selectionMode` を `CONTENT_FLAGS` に載せ、content は `storage.onChanged` で表示方法の切替に即追従（インラインへ切替えたら開いているバブルを閉じる）
- **バブル UI**: `#__rt_sel_bubble` に `all:initial` + `__rt-sel-*` 接頭辞でページ CSS と隔離（Shadow DOM 不使用・selection-translator.css）。FAB と同じフラットデザイン（生成り・墨・朱のベタ塗り + 1px 境界 + 左の朱バー、ぼかし最小の単一影、グラデ/テクスチャなし）+ ダークモード。状態は `loading`(淡い左バー)/`result`(墨本文+コピーボタン)/`error`(濃い朱・理由を i18n 展開＝`statusNoKey`/`statusBadKey`/`statusQuotaDaily`/`statusNetwork` を fab/popup と共有)。消去は バブル外 pointerdown・Esc・選択解除(`selectionchange`)・スクロール/リサイズで anchor 消失時。`__rtSelectionLoaded` の runtime/version-aware 冪等ガード + `contextAlive()`/`shutdown()` で context 失効ハードニング
- **Shadow DOM 内の選択に対応（`deepSelection`・本命）**: `window.getSelection()` は Chrome/Firefox とも shadow tree 内の選択を貫通せず anchorNode が shadow host になる（Reddit のサイドパネル等 Web Components で「翻訳できるエリア/できないエリア」が出る主因）。`deepSelection()` は通常選択が空なら ① anchorNode=host の `shadowRoot.getSelection()`（Chromium/Firefox がサポート）へネスト降下 → ② 開いた shadow root の全走査（`scanShadowSelection`・translator.js の collectNodes と同方針）で中の選択を拾う。直近に当たった shadow root を `lastSelRoot` にキャッシュし scroll/selectionchange 連打での再走査を避ける。rect は `rectFor` が range の rect → 空なら anchorNode 周辺へフォールバック。`reposition`/`onSelChange` も `deepSelection` 基準（shadow 選択中に誤って閉じない）
- **既知の制限**: iframe 内の選択は対象外（トップフレームのみ常駐＝広告枠コスト回避。fab.js と同方針）。closed shadow root は仕様上たどれない（open のみ・translator.js と同じ）
